# Проверка MVP KPI

Ниже — пошаговые ручные проверки для KPI‑1..KPI‑5 из текущего ТЗ. Перед началом убедитесь,
что backend, Redis, MinIO и воркеры запущены.

## KPI‑1: повторный POST /documents:generate с тем же Idempotency‑Key
1. Загрузить шаблон (DOCX) через `/api/v1/templates`.
2. Создать версию шаблона через `/api/v1/templates/{id}/versions`.
3. Запустить генерацию документа через `/api/v1/documents/generate` с заголовком `Idempotency-Key`.
4. Повторить запрос с тем же `Idempotency-Key` и идентичным payload.
5. Убедиться, что `document_version_id`/`run_id` совпадает с первым ответом.

## KPI‑2: любой /v1 бизнес‑роут без X‑Tenant → 400
1. Вызвать любой бизнес‑эндпоинт `/api/v1/*` без заголовка `X-Tenant`.
2. Убедиться, что ответ — `400` с сообщением о необходимости tenant.

## KPI‑3: строгий выбор (template_code, version) и запрет удаления используемой версии
1. Создать шаблон с `template_code` и версию `version`.
2. Сгенерировать документ, указав `(template_code, version)` в `/api/v1/documents/generate`.
3. Попытаться удалить используемую версию через `/api/v1/templates/{id}/versions/{version_id}`.
4. Убедиться, что получен `409 Conflict`.

## KPI‑4: событие → outbox → webhook доставлен ≤60 секунд
1. Сконфигурировать webhook получателя (глобально или на уровне tenant).
2. Выполнить событие (например, генерация документа или выдача СИЗ).
3. Проверить запись в `outbox` и факт доставки webhook (лог получателя/метрики).
4. Убедиться, что доставка заняла ≤60 секунд.

## KPI‑5: оценка рисков → детерминированные карточки и план мероприятий
1. Убедиться, что справочники рисков/опасностей заполнены.
2. Выполнить оценку рисков через `/api/v1/risks/assessments`.
3. Повторить оценку с теми же входными данными.
4. Убедиться, что карточки рисков и план мероприятий идентичны.
