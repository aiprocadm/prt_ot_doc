# Проверка MVP KPI

Ниже — пошаговые ручные проверки для KPI‑1..KPI‑5. Перед началом убедитесь, что backend, Redis, MinIO и воркеры запущены.

## KPI‑1: генерация документа из шаблона < 2 минут
1. Загрузить шаблон (DOCX) через `/api/v1/templates`.
2. Создать версию шаблона через `/api/v1/templates/{id}/versions`.
3. Запустить генерацию документа через `/api/v1/documents/generate` с `Idempotency-Key`.
4. Дождаться статуса `completed` в `/api/v1/documents/jobs/{id}`.
5. Убедиться, что время выполнения < 2 минут.

## KPI‑2: запуск пакета документов для сотрудника < 5 минут
1. Создать pack через `/api/v1/packs` с нужными template/version.
2. Запустить pack: `/api/v1/packs/run` (Idempotency-Key обязателен).
3. Отслеживать `/api/v1/packs/runs/{run_id}`.
4. Убедиться, что итоговый статус `completed` и время < 5 минут.

## KPI‑3: фиксация выдачи СИЗ и отражение в журнале
1. Создать норму выдачи `/api/v1/ppe/norms`.
2. Зарегистрировать выдачу `/api/v1/ppe/issues`.
3. Проверить, что запись появилась в журнале `/api/v1/ppe/journal`.

## KPI‑4: запись результатов обучения и доступ к сертификату
1. Создать программу обучения `/api/v1/training/programs`.
2. Назначить сессию `/api/v1/training/sessions`.
3. Зафиксировать результат `/api/v1/training/results`.
4. Убедиться, что сертификат доступен по `/api/v1/training/results/{id}/certificate`.

## KPI‑5: регистрация инцидента с отчётом и уведомлением
1. Создать инцидент `/api/v1/incidents`.
2. Добавить результаты расследования и меры `/api/v1/incidents/{id}/actions`.
3. Сгенерировать отчёт `/api/v1/incidents/{id}/report`.
4. Убедиться, что webhook событие доставлено (outbox log).
