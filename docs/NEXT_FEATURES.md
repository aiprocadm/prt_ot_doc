# NEXT_FEATURES

> **DEPRECATED (2026-05-04).** Содержание этого файла полностью покрыто разделом **B (полный объём vNext)** канонического ТЗ — [`docs/spec/TZ_FULL_UNIFIED.md`](spec/TZ_FULL_UNIFIED.md), и разделами `§7..§30` в [`docs/spec/PLATFORM_VNEXT_UPGRADE_SPEC.md`](spec/PLATFORM_VNEXT_UPGRADE_SPEC.md). Не используйте этот файл как источник требований. Кандидат на удаление в следующей волне (см. `docs/CLEANUP_CANDIDATES.md` → Wave 4).

Дорожная карта функциональности, ещё не реализованной полностью, но логически необходимой для платформы документооборота ОТ/ПБ/Эко. Блоки опираются на существующее ядро (тенанты, компании, люди, пакеты документов, риск-оценка, файловое хранилище, Celery/Redis, idempotency, аудит).

## Модуль обучения (LMS, удостоверения)
- **Цель:** планировать и фиксировать обучение персонала, выдачу удостоверений и контроль сроков действия.
- **Ключевые сущности/эндпоинты:** каталоги курсов, планы обучения по ролям/должностям, расписание сессий, регистрация на обучение, попытки тестов, выдача удостоверений с привязкой к `Training`/`Permit`, отчёты о просрочках. REST/GraphQL эндпоинты для CRUD курсов, расписания, попыток, загрузки сертификатов в файловое хранилище.
- **Зависимости:** `Person`, `Position`, `Training`, `Permit`, `File`, аудит событий, idempotency, уведомления через Celery.

## Расширенные сценарии ОТ/ПБ/Эко
- **Цель:** покрыть реальные кейсы: допуск на объект, расследование происшествий, проверки, ОПО, учёт вредных факторов, наряды-допуски.
- **Ключевые сущности/эндпоинты:** расширенные `DocumentPack` для сценариев «выход на объект», «несчастный случай», «плановая/внеплановая проверка», регистрация `Incident`, `Checklist`/`Inspection`/`Violation`/`CorrectiveAction`, наряды-допуски и согласования, учёт опасных факторов/СИЗ, интеграция с NPA для ссылок на нормативку. Эндпоинты для запуска сценариев, журналирования хода расследований, загрузки фото/актов.
- **Зависимости:** `Company`, `Site`, `Person`, `RiskHazard`, `RiskAssessment`, `DocumentPack`, `Checklist`/`Inspection`, файловое хранилище, аудит и outbox для уведомлений.

## Аналитика и дашборды
- **Цель:** дать менеджерам метрики по ОТ/ПБ/Эко (статусы пакетов, динамика рисков, обучение, инциденты).
- **Ключевые сущности/эндпоинты:** агрегированные представления по `DocumentGenerationJob`/`PipelineRun`, статистика по `RiskAssessment`/`RiskMap`, отчёты по `Training`/`Permit`/`MedicalExam`, показатели по `Incident` и `CorrectiveAction`. API для выборок/виджетов, подготовка материалов для BI (CSV/Parquet выгрузки, подписки на отчёты).
- **Зависимости:** источники данных из ORM, `AuditLog`/`JournalEntry` для событий, очереди Celery для расчётов, настройка кэширования (Redis) и materialized views.

## Конструктор процессов и маршрутов согласования
- **Цель:** дать no-code/low-code настройку последовательностей действий: сбор данных, проверки, подписи, уведомления.
- **Ключевые сущности/эндпоинты:** дизайнер процессов (узлы/переходы), библиотеки шагов (генерация пакета, загрузка файла, уведомление, вебхук), схемы согласования с ролями и сроками, исполнение с сохранением истории (`PipelineRun`, будущий `WorkflowInstance`). REST для CRUD процессов, запуска инстансов, постановки задач исполнителям, webhooks.
- **Зависимости:** текущие `DocumentPack`/`PipelineRun`, `IdempotencyKey`, RBAC/ABAC, Celery для фоновых шагов, audit/outbox для трассировки.

## Реальные интеграции (1С, ЭДО, ФРДО, ЕИСОТ)
- **Цель:** обмен данными и документами с внешними системами, чтобы исключить ручной ввод.
- **Ключевые сущности/эндпоинты:** коннекторы/адаптеры (REST/SOAP/file), планировщик синхронизаций, карта сопоставления полей (Person/Company/Docs ↔ внешние справочники), обработка ошибок и ретраев. Эндпоинты/вебхуки для входящих событий, статусы интеграционных задач.
- **Зависимости:** `Outbox`, `JournalEntry`, idempotency, файловое хранилище, безопасное хранение секретов, очередь Celery, фича-флаги (`FeatureEnablement`).

## Улучшенная мультиарендность и биллинг
- **Цель:** гибко управлять тарифами, квотами и делегированным администрированием между арендаторами.
- **Ключевые сущности/эндпоинты:** управление `Tenant` планами/квотами, биллинговые аккаунты, лимиты на генерации/хранилище/пользователей, кастомные домены, аудит арендных операций, API-ключи для интеграций, отчётность/счета. Сервис учёта потребления и выставления инвойсов.
- **Зависимости:** `Tenant`, `ApiKey`, `Feature`/`FeatureEnablement`, метрики генерации (`DocumentGenerationJob`, `PipelineRun`), S3/Redis usage, внешняя платёжная система.

## Веб-интерфейс и админка
- **Цель:** полнофункциональная UI/админка для всех доменных блоков без прямых запросов к БД.
- **Ключевые сущности/эндпоинты:** SPA для CRUD `Company`/`Person`/`Pack`, визуальные конструкторы пакетов/процессов, страницы аналитики, аудит и управление доступами. Отдельные админ-API (массовые операции, импорты), UI для управления фича-флагами и интеграциями.
- **Зависимости:** существующие REST API, будущие endpoints из блоков выше, SSO/JWT, rbac/abac, статическая сборка фронтенда/NGINX.
