## 1. Цели (Goals)
- Дать единую платформу для управления документами и процессами охраны труда (ОТ), промышленной безопасности (ПБ), экологии и смежных направлений.
- Обеспечить полный жизненный цикл документов: шаблон → генерация → подписание → хранение → аудит.
- Свести в одной системе обучение, медосмотры, СИЗ, проверки, инциденты и риск-оценку.
- Поддержать интеграции с внешними системами (1С, ФРДО, ЕИСОТ) через webhooks/outbox.
- Сформировать масштабируемую и безопасную архитектуру для мульти-арендных клиентов.

## 2. Аналогии (Analogies)
- **ERP‑подход**: единая точка управления операциями и документами для ОТ/ПБ.
- **LMS‑подход**: обучение и аттестации сотрудников как образовательный контур.
- **DMS‑подход**: контроль версий шаблонов и архив документов с политиками хранения.

## 3. Core + Modules
- **Core**: аренды, компании, персонал, шаблоны, документы, аудит, outbox, интеграции, биллинг.
- **Modules** (включаются по фича‑флагам/тарифам): обучение, медосмотры, СИЗ, проверки, инциденты, риск‑оценка, отчёты, интеграции.
- Архитектура модульная: модули используют базовые сервисы Core (тенантность, хранение, аудит, idempotency).

## 4. Multi‑tenancy
- Изоляция на уровне БД: все доменные сущности содержат `tenant_id`.
- Обязательные заголовки `X‑Tenant‑Id` для запросов.
- Сквозное логирование с `tenant_id`, сегрегация данных и метрик.

## 5. RBAC + ABAC
- RBAC: роли уровня аренды (owner/admin/manager/user/auditor).
- ABAC: политики на уровне объекта (компания, площадка, сотрудник, документ).
- Политики хранятся в отдельном хранилище (policy store) и применяются к запросам.

## 6. Аудит (Audit)
- Все операции изменения данных пишут записи в `audit_log`.
- Аудит содержит actor, объект, старые/новые значения, `trace_id` и `tenant_id`.
- Аудитная информация хранится минимум 5 лет.

## 7. Сущности (Entities)
- **Аренда и пользователи:** tenant, user, role, policy, api_key.
- **Оргструктура:** company, site, department, position, person.
- **Документы:** template, template_version, document_job, document_file, file_object.
- **СИЗ:** ppe_norm, ppe_issue, ppe_return, ppe_stock.
- **Обучение:** training_program, training_session, training_result.
- **Медицина:** medical_exam, medical_conclusion.
- **Инциденты и риски:** incident, risk_assessment, risk_control.
- **Проверки:** inspection, checklist, violation, corrective_action.
- **Служебные:** webhook_outbox, audit_log, notification.

## 8. Документы, шаблоны и версионирование
- Шаблоны DOCX хранятся в S3/MinIO с версионностью.
- Генерация документов асинхронная через очереди.
- Итоговые файлы сохраняются как `file_object` и версионируются.
- Документы доступны по подписанным ссылкам, срок жизни управляется.

## 9. Сроки и обязательства (Deadlines/Obligations)
- Обязательные SLA: P95 < 400 мс для чтений, P99 < 2 с для команд без генерации файлов.
- Документы и журналы сохраняются не менее 5 лет.
- Отчётность формируется по графику и доступна по запросу.

## 10. Обучение (Training)
- Управление программами, расписаниями, сессиями и результатами.
- Импорт сотрудников и результатов из внешних систем.
- Контроль сроков и допусков, автоматические уведомления.

## 11. Медосмотры (Medical)
- Учёт периодических и предварительных медосмотров.
- Хранение заключений и сроков годности.
- Интеграции с внешними лабораториями/медцентрами (webhooks).

## 12. СИЗ (PPE)
- Нормы выдачи по должностям и площадкам.
- Журнал выдачи, возврата и списания.
- Контроль остатков и предупреждения при нехватке.

## 13. Инциденты (Incidents)
- Регистрация инцидентов, классификация, связи с рисками.
- План действий и контроль выполнения.
- Генерация отчётных форм и уведомления.

## 14. Риски (Risk)
- Реестр рисков и оценка вероятности/ущерба.
- Меры контроля и пересмотр оценок.
- Связь с проверками, инцидентами и обучением.

## 15. Проверки и инспекции (Inspections)
- Чек‑листы, аудит площадок, фиксация нарушений.
- Корректирующие действия и контроль сроков.
- Хранение фото‑доказательств и протоколов.

## 16. Отчёты (Reports)
- Шаблоны отчётов по документам, обучению, СИЗ, инцидентам.
- Генерация отчётов асинхронно с очередями.
- Экспорт в PDF/XLSX, доступ по подписанным ссылкам.

## 17. Outbox/Webhooks
- Шина событий построена на outbox‑паттерне.
- События доставляются повторно с экспоненциальной задержкой.
- Поддержка интеграций 1С, ФРДО, ЕИСОТ и кастомных webhook‑получателей.

## 18. API / NFR
- REST API `/api/v1` с обязательным `Idempotency-Key` для команд.
- Формат ответа: `Envelope { data, error, correlation_id }`.
- Основной контракт: `docs/openapi.yaml`.
- Нефункциональные требования: отказоустойчивость, трассировка, мониторинг, масштабирование.

## 19. Security
- JWT аутентификация, ротация ключей, refresh flow.
- RBAC + ABAC, принцип минимально необходимых прав.
- Антивирусная проверка (ClamAV), MIME‑проверка, лимиты загрузки.
- Секреты хранятся только в secret manager/ENV.

## 20. Монетизация
- Тарифы на основе количества сотрудников, документов и модулей.
- Ограничения и фича‑флаги определяются подпиской.
- Поддержка пробного периода и счетов на оплату.

## 21. MVP KPI
- **KPI‑1:** успешная генерация документа из шаблона < 2 минут.
- **KPI‑2:** запуск пакета документов для сотрудника < 5 минут.
- **KPI‑3:** фиксирование выдачи СИЗ с отражением в журнале.
- **KPI‑4:** запись результатов обучения и доступ к сертификату.
- **KPI‑5:** регистрация инцидента с отчётом и уведомлением.
