# Группы по электробезопасности (903н) у бригады наряда-допуска

**Дата:** 2026-06-23
**Статус:** Design (новый контур; пользователь — «продолжай по роадмап», выбрал направление 1)
**Контур:** наряды-допуски §16, электроустановки (903н) + карточка персоны

## Контекст и решения пользователя

903н требует, чтобы у членов бригады электроработ были группы по электробезопасности
(производитель работ, члены — не ниже определённой; ответственный руководитель — выше).
Сейчас группа нигде не хранится. Два решения пользователя через AskUserQuestion:

1. **Хранение — на персоне, БЕЗ миграции:** структурная запись в существующем `Person.qualifications`
   (JSON list). Группа = квалификация персоны (концептуально верно), переиспользуема всеми нарядами.
2. **Валидация — показ + мягкая готовность:** UI показывает группы + предикат готовности (кто ниже
   минимума по роли), как `closing_readiness`; **без жёсткого FSM-гейта** выдачи.

Дивиденд «без миграции» снова держится (`qualifications` — уже JSON).

Ветка: `feat/work-permit-electrical-groups` стеком поверх `feat/work-permit-gas-analysis-editor`
(электро-вид и его секции — в актуальном состоянии). Мержить по порядку.

## Модель данных (без миграции)

`Person.qualifications: list[dict]` (уже есть). Новая структурная запись:
```json
{ "kind": "electrical_safety_group", "level": "IV", "valid_until": "2027-01-01",
  "name": "Группа по электробезопасности", "issued_at": "...", "issuer": "...", "document": "..." }
```
Схема `QualificationRecord` (backend/app/schemas/person.py) получает **опциональное поле**
`level: str | None` (JSON-хранение — миграции нет). `level` свободен в схеме; домен валидирует ∈ I–V.

## Backend

### Чистый модуль `domains/work_permits/electrical_groups.py`
(без I/O, как `lifecycle.py`/`profiles.py`)
```python
GROUP_ORDER = ["I", "II", "III", "IV", "V"]   # порядковый ранг

ROLE_MIN_GROUP = {            # упрощённые дефолты 903н (контекст ≤1000В), документировано
    "issuer": "IV", "supervisor": "IV", "admitter": "IV",
    "foreman": "III", "member": "III", "observer": "III",
}

def current_group(qualifications, as_of) -> str | None:

    Действует, если valid_until None или valid_until >= as_of. None если нет."""

def rank(level) -> int:        # индекс в GROUP_ORDER, -1 если неизвестно

def meets_minimum(group, role) -> bool:
    """group не ниже ROLE_MIN_GROUP[role]; нет требования по роли → True;
    group None или неизвестно → False (когда требование есть)."""

def readiness(members) -> dict:
    """members: list[{person_id, role, group}]. → {ok: bool,
```

### Обогащение read (только `work_type == "electrical"`)
- `WorkPermitMemberRead.electrical_group: str | None` (резолв из персоны на `as_of=today`).
- `WorkPermitRead.electrical_group_readiness: ElectricalGroupReadiness | None`
  (`{ok: bool, insufficient: [...]}`), считается только для электро; иначе `None`.
- Деталь-роут (`api/routes/work_permits.py`, ~строка 188): для электро-наряда загрузить
  `Person.qualifications` всех членов одним запросом (по `person_id ∈ members`), резолвить группу,
  передать в `_member_schema`, собрать `readiness`. Не-электро: поля `None`/пропущены, лишних
  запросов нет (гейт по `work_type`).

### Demo-seed
Производителю (`foreman`) демо-наряда электроустановок (`WP-ELEC-DEMO`, если есть; иначе пропустить
идемпотентно) — записать в `Person.qualifications` группу `IV` (kind=electrical_safety_group),
чтобы фича была видна «из коробки». Идемпотентно (не дублировать запись).

## Frontend

### Карточка персоны — точечный контрол группы (`PersonFormDialog`)
Форма сейчас НЕ несёт `qualifications` и update-API заменяет список **целиком** → **footgun
затирания**. Решение:
- Форма загружает существующие `qualifications` из `initialData` в скрытое состояние (default `[]`).
- Контрол: `select` группы (I–V + «—» для пусто) + `Input` «действует до» (date).
- `toBody`: собирает `qualifications = [...прочие записи (kind != electrical_safety_group), новая
  электро-запись (если группа выбрана)]`. Прочие квалификации СОХРАНЯЮТСЯ. Если группа снята (`—`) —
  электро-запись удаляется, прочие целы.
- На открытии (edit) — извлечь текущую электро-группу из `qualifications` в поля формы.

### Деталь электронаряда
- Бригадная панель: у каждого члена — бейдж группы (`electrical_group` из read; «—» если нет).
- Баннер готовности: если `electrical_group_readiness.ok == false` — список членов ниже минимума
  («роль X: группа Y < требуется Z»). Мягко (предупреждение, не блок). Только `work_type=="electrical"`.

## Тестирование

**Backend (pytest):**
- `electrical_groups` юниты: `current_group` (высшая из нескольких; истёкшая исключена; пусто→None);
  `meets_minimum` (точно на минимуме / ниже / нет требования / None-группа); `readiness` (ok при всех
  достаточных; insufficient перечисляет нарушителей с required).
- `QualificationRecord.level` принимается схемой; легаси-записи без `level` не ломаются.
- Обогащение read: электро-наряд возвращает `electrical_group` у членов + `electrical_group_readiness`;
  не-электро наряд — `None` (нет лишних запросов — проверить через данные, не моки).

**Frontend (vitest):**
- `PersonFormDialog`: установка группы пишет электро-запись; **merge сохраняет** заранее заданную
  тренинг-квалификацию (footgun-тест); снятие группы удаляет только электро-запись; load заполняет поле.
- Деталь электронаряда: рендер групп у членов; баннер готовности при наличии нарушителя; для не-электро
  наряда баннер/группы не показываются.

## Изоляция и границы

- `electrical_groups.py` — чистый домен, тестируется без БД (как `profiles.py`).
- Обогащение — единичный гейт по `work_type` в read-пути; запись групп персон не меняется (wholesale-replace
  API переиспользуется, форма шлёт полный merged-список).
- Контрол персоны — точечный (только электро-группа), НЕ общий редактор квалификаций (вне объёма).

## Отложено (явно)

1. Минимумы в зависимости от напряжения (>1000В строже — `ROLE_MIN_GROUP` пока единый ≤1000В-набор).
2. Полноценный редактор квалификаций персоны (тренинги/допуски) — отдельный контур.
3. История групп / № протокола проверки знаний / периодичность — сейчас одна текущая запись.
4. Жёсткий FSM-гейт выдачи по группам (выбрана мягкая готовность).
5. Печать групп в бланк 903н — кандидат на следующий срез (read уже отдаёт группы).
