# Фрагменты поиска в архиве (безопасный рендер)

## Контекст

Страница `frontend/src/pages/ArchiveSearch.tsx` показывает поле `snippet` из API поиска. Раньше использовался `dangerouslySetInnerHTML`, что позволяло выполнить XSS, если в индекс поиска попадёт строка с HTML/атрибутами событий (данные из документов, вложений, пользовательского текста).

## Текущее поведение

Сниппет выводится как **текст** (`children` ячейки таблицы), с классами `whitespace-pre-wrap break-words` для читаемости длинных фрагментов.

Бэкенд (`SearchService._build_snippet` в `backend/app/modules/search/service.py`) формирует сниппет как подстроку из `title`, `subtitle` и строкового представления `preview_payload` — это не «безопасный HTML», а произвольный текст.

## Регрессия

Тест: `frontend/src/__tests__/ArchiveSearch.test.tsx` (кейс «renders snippet as plain text without HTML injection») — проверяет, что строка с тегами не создаёт `<img>` и не выставляет маркер на `window`.

## Если понадобится подсветка совпадений

Нельзя возвращаться к сырому HTML без санитизации (например DOMPurify с жёстким allowlist) или без экранирования с последующей разметкой только доверенных узлов.
