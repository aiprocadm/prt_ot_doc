# RELEASE CANDIDATE AUDIT

Дата прохода: 2026-03-15.

## Что обнаружено в финальном прогоне
- Критический дефект в backend endpoint `PATCH /api/v1/tasks/{task_id}`: в audit-логировании использовалась переменная `access`, которая не была внедрена в сигнатуру обработчика, что приводило к `NameError` и срыву обновления задач.
- Полный `ruff check` по backend/tests показывает большой исторический хвост (сотни предупреждений E402/F841/E741/F401) — это системная проблема качества, а не один локальный дефект.
- Smoke-скрипт в SQLite fallback-режиме подтверждает известное ограничение миграций: `JSONB` в initial migration не компилируется для SQLite.
- Frontend typecheck стабилен, но production build в текущем окружении работает нестабильно по времени и требует отдельного CI-подтверждения на чистом runner.

## Что исправлено в этом проходе
- Исправлена сигнатура `update_task`: добавлена явная dependency-инъекция `AccessContext`, чтобы audit-контур использовал корректный `access.user` и endpoint завершался успешно.
- Проверен целевой backend regression на статусах задач (`tests/test_task_status.py`) — сценарии `status endpoint` и `not found` проходят.
- Подтверждена применимость миграций в offline/fallback режиме; зафиксировано ограничение SQLite/JSONB как остаточный риск RC.

## Что стабилизировано
- Убрана runtime-ошибка в критичном бизнес-потоке обновления задач (CRUD + audit trail).
- Подтверждена работоспособность ключевого smoke-критерия по задачам: чтение статуса и корректный `404` при несуществующем объекте.

## Остаточные риски
- Полный lint/test контур по репозиторию пока не зеленый из-за накопленного технического долга вне зоны точечного фикса.
- Полноценный smoke (`scripts/smoke.sh`) в локальном SQLite режиме ограничен несовместимостью JSONB-миграций.
- Для финального release sign-off нужен отдельный прогон полного CI на целевом окружении (PostgreSQL + frontend build/test matrix).
