# RELEASE CANDIDATE AUDIT

Дата прохода: 2026-03-15.

## Что обнаружено в финальном прогоне
- В regression-наборе было 22 падения, но большинство оказались следствием одного класса проблем: устаревшие тестовые контракты после ужесточения tenancy (`X-Tenant`) и унификации путей/DTO.
- Основные рассогласования:
  - тесты статусов документов/analytics/export/search вызывали бизнес-роуты без `X-Tenant`;
  - тесты файлов ожидали legacy-префикс `tenant/...`, тогда как runtime использует `tenants/...`;
  - replace API тестировался через устаревшие endpoint’ы, не соответствующие текущему модулю `replace-runs`;
  - часть негативных RBAC/ABAC тестов ожидала старый код причины отказа.

## Что исправлено
- Обновлены backend integration/unit тесты под текущий API-контракт и требования tenancy.
- Переведены replace smoke-тесты на актуальный сценарий: `replace-map -> dry-run -> apply -> rollback`.
- Актуализированы проверки файлового ключа под текущий префикс `tenants/...`.
- Уточнены ожидания по policy-engine (причины отказов) согласно текущему движку авторизации.

## Что стабилизировано
- Набор ранее падающих критических тестов приведен в зеленое состояние.
- Подтверждена работоспособность ключевых RC-потоков:
  - смена статусов документов;
  - аналитика/поиск/экспорт;
  - загрузка/скачивание архивов;
  - replace dry-run/apply/rollback;
  - базовые policy/RBAC проверки.

## Остаточные риски
- В полном `pytest` остаются не только контрактные, но и инфраструктурные/доменные проверки; для полного sign-off нужен отдельный полный прогон на целевом CI-стенде.
- Предупреждения third-party библиотек (`pydantic`, `jose`) не критичны, но создают шум в логах.
