# Pilot readiness checklist (phase 6)

Цель: ответить «Можно ли безопасно подключать первого платящего клиента?»

## 1) Техническая готовность

- [ ] Прогнаны сценарии из `docs/pilot/scenarios.md`.
- [ ] Миграции проходят на пустой БД и на предыдущей версии.
- [ ] Генерация документов и пакетов работает стабильно.
- [ ] Нагрузочные лимиты (`RATE_LIMIT_*`, `MAX_UPLOAD_SIZE`) подтверждены.

## 2) Бизнес-готовность

- [ ] Организационная структура создаётся без ручных операций БД.
- [ ] Инспекции и предписания проходят полный цикл.
- [ ] Обучение/обязательства формируют дедлайны и напоминания.
- [ ] Экспорт/подписание документов работают корректно.

## 3) Безопасность

- [ ] Multi-tenant изоляция подтверждена (см. `docs/pilot/tenant-isolation-report.md`).
- [ ] Проверены права доступа на ключевых эндпоинтах.
- [ ] Аудит фиксирует действия по документам и задачам.
- [ ] Webhooks отправляются только в рамках своего tenant.

## 4) Операционная готовность

- [ ] Есть бэкап/restore процедуры для БД и object storage.
- [ ] Известен порядок rollback (см. `docs/ops/migrations-and-rollback.md`).
- [ ] Обработаны failure-сценарии (см. `docs/ops/failure-scenarios.md`).
- [ ] Система мониторинга подключена (метрики outbox/celery).

## 5) Готовность для non-developers

- [ ] Все шаги выполняются через UI/API без доступа к БД.
- [ ] Есть инструкции для оператора (scenarios + failure-scenarios).
- [ ] Настройки вынесены в `.env` и не требуют правки кода.

## 6) Финальное решение

- [ ] ✅ GO — все разделы пройдены.
- [ ] ❌ NO-GO — хотя бы один раздел не пройден.
