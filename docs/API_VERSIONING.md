# OPS-73 (разд. 73): версионирование API и управляемое устаревание

> ТЗ (Доп. №4, разд. 73): «Как только появится хоть один внешний потребитель —
> ломать контракты станет нельзя. Это дёшево заложить сейчас и очень дорого
> вводить потом».

## Политика версий (разд. 73.1)

- **Версия живёт в пути**: `/api/v1/…`, следующая мажорная — `/api/v2/…`.
  Префикс задаётся настройкой `API_V1_PREFIX` (`core/config.py`) и монтируется
  одной строкой в `api/app.py` — вторая версия монтируется рядом, не заменяя первую.
- **Semver контрактов**: ломающие изменения — только в новой мажорной версии;
  добавления (новое необязательное поле, новый эндпоинт, новое значение enum) —
  в текущей.
- **Что считается ломающим** — канонический список хранится программной
  константой `product_spec.API_BREAKING_CHANGES` и читается контрактным гейтом:
  `remove_field`, `rename_field`, `change_type`, `change_semantics`,
  `tighten_validation`. Удаление эндпоинта — частный случай `remove_field`.

## Управляемое устаревание (разд. 73.2)

Пять этапов ТЗ отображены на механизмы:

| Этап ТЗ | Механизм |
|---|---|
| Анонс (за 6–12 мес) | запись в реестре `core/api_deprecation.py` + строка в CHANGELOG; контрактный тест не пропустит срок короче 6 месяцев |
| Параллельная работа | контрактный тест: устаревшая поверхность обязана существовать до даты sunset |
| Предупреждения | `middleware/api_deprecation.py`: заголовки `Deprecation` (RFC 9745, формат `@unix-время`), `Sunset` (RFC 8594, HTTP-дата), `Link rel="successor-version"` на **каждом** ответе поверхности, включая ошибки |
| Мониторинг использования | метрика `api_deprecated_requests_total{path_prefix, status_class}` («сколько», с разрезом по статусу: живая интеграция = `2xx`, сканерный шум по отключённой поверхности = `4xx`) + структурный лог `api.deprecated_request` с арендатором и статусом («кто») |
| Отключение | только после даты sunset **и** нулевого трафика по метрике; удаление ручки раньше срока валит контрактный гейт |

### Как объявить эндпоинт устаревшим

1. Добавьте запись в `API_DEPRECATIONS` (`backend/app/core/api_deprecation.py`):
   префикс пути, дата анонса, дата sunset (не раньше чем через 6 месяцев),
   преемник. Пустого преемника не бывает: «этого больше не будет» без «куда
   переходить» — не deprecation, а угроза.
2. Middleware, метрика и контрактный тест подхватят запись сами — реестр
   объявлен данными ровно для этого.
3. Строка в CHANGELOG — это и есть «анонс в changelog» из ТЗ.

### Как отключить устаревшее

Только когда выполнены **оба** условия: дата sunset наступила и
`api_deprecated_requests_total{status_class="2xx"}` по префиксу не растёт.
Смотреть надо именно на `2xx`: счётчик `4xx` растёт от интернет-сканеров и не
упадёт до нуля никогда. Затем удалить ручку и запись реестра в одном PR —
после sunset гейт разрешает исчезновение операций этой поверхности.

## Контрактная стабильность (разд. 73.3)

- **Гейт в CI**: `tests/contract/test_api_breaking_changes_contract.py`
  (маркер `contract`, job `openapi-contract` в `ci.yml`) сравнивает
  `app.openapi()` с базлайном `docs/stabilization/openapi_routes_baseline.json`.
  Красный билд: исчезновение операции или схемы, **удаление поля из схемы,
  смена типа поля** (базлайн хранит подпись полей каждой схемы). Добавления —
  законная эволюция, но базлайн обязан обновляться **в том же PR**
  (`python scripts/ci/check_openapi_snapshot.py --snapshot`): свежесть проверяет
  отдельный тест, иначе у гейта появляется слепое окно на «добавили и удалили
  между снимками».
- **Что гейт НЕ ловит механически** (честное ограничение): `change_semantics`
  (то же поле стало значить другое) и `tighten_validation` (ужесточение проверок
  без смены схемы). Эти категории остаются на ревью человеком.
- Snapshot-гард ARCH-4 (`check_openapi_snapshot.py`) остаётся отдельным
  инструментом для рефакторингов: он падает на любом дрейфе и в CI не стоит.

## Известные ограничения и хвосты

- **Версионирование вебхук-payload'ов** (разд. 73.3) — сделано срезом-2:
  `schema_version` в теле + `X-Webhook-Schema-Version` в заголовке, контракт
  подписчика — [WEBHOOKS.md](WEBHOOKS.md), гейт —
  `tests/contract/test_webhook_payload_contract.py`.
- Аномалия `/api/v1/v1/…` у `approval_signing_v1` (вложенный префикс) — уже
  опубликованный путь; переименование само было бы ломающим изменением, поэтому
  исправлять его можно только через этот же процесс deprecation.
- Уведомления потребителям (письма) — организационный канал поверх заголовков;
  машинный канал (заголовки + метрика) первичен.
